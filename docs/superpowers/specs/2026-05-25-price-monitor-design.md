# 第三方平台价格监控与钓鱼溯源系统 设计文档

## 概述

低频率自动化监控第三方平台（闲鱼、淘宝为首期，后续扩展京东、拼多多）上的乱价行为，并通过 AI 驱动的钓鱼话术溯源渠道归属。

**核心目标**：
- 降低第三方平台乱价行为，提升整体好友付费率
- 构建良好生态渠道，实现渠道可持续发展

---

## 整体架构

```

┌─────────────────────────────────────────────────────────────┐
│                    Scheduler (定时器)                         │
│          Windows Task Scheduler                              │
│             每天 2 次 (随机偏移 ±1.5h)                       │
└──────────────────────────┬──────────────────────────────────┘
                           │ 触发
┌──────────────────────────▼──────────────────────────────────┐
│                    Orchestrator (调度器)                      │
│  1. 读取配置 → 2. 加载产品列表 → 3. 轮询平台 → 4. 汇总报告    │
└──────┬──────────────┬──────────────┬───────────────────────┘
       │              │              │
       ▼              ▼              ▼
┌──────────┐   ┌──────────┐   ┌──────────┐
│ 闲鱼 Agent│   │ 淘宝 Agent│   │ 后续平台  │
│          │   │          │   │ (JD/PDD) │
└─────┬────┘   └────┬─────┘   └────┬─────┘
      │             │              │
      ▼             ▼              ▼
┌─────────────────────────────────────────────────────────────┐
│              Playwright Browser Farm (浏览器池)               │
│   - 每次启动独立浏览器上下文 (指纹随机化)                       │
│   - 住宅代理轮换                                             │
│   - 完整的真人行为模拟                                        │
└─────────────────────────────────────────────────────────────┘
```

### 每个 Agent 内部流程

```
搜索 → DOM提取列表 → LLM判价 → 有乱价？→ 钓鱼聊天 → 记录溯源
                          ↓ 否
                       跳过
```

### 关键设计原则

- **Agent 隔离**：每个平台有独立 Agent，互不影响
- **浏览器复用**：单次运行中复用浏览器上下文，避免反复登录
- **会话隔离**：每次运行使用全新浏览器指纹，两次运行无关联
- **LLM 驱动**：搜索词生成、乱价判断、钓鱼话术全部由 LLM 处理

## 反检测策略（核心）

### 分层防御体系

```
Layer 1: 网络层
  ├── 住宅代理（静态ISP代理，非机房IP）
  ├── IP 属地匹配账号归属地
  └── 每次运行隔 ≥6 小时，运行时间随机偏移 ±90 分钟

Layer 2: 浏览器指纹层
  ├── 随机 User-Agent（Windows Chrome 真实版本池）
  ├── WebGL、Canvas、AudioContext 指纹随机化
  ├── 随机 Viewport（1366×768 ~ 1920×1080）
  ├── 时区/语言/字体 匹配 IP 归属地
  └── 禁用 WebDriver 标志

Layer 3: 行为层（最重要）
  ├── 鼠标轨迹：贝塞尔曲线
  ├── 滚动行为：先快后慢，偶尔停顿
  ├── 输入行为：不等速打字，有删除重输
  ├── 搜索行为：打开首页→等→搜索框→输入→等→搜索
  ├── 浏览行为：上下滚动，随机点进 1-2 个商品
  └── 时间缩放：每一步延时 0.8~1.5 随机因子

Layer 4: 节奏层
  ├── 同账号一天只搜 1 次
  ├── 每次搜索用不同关键词
  ├── 交替使用不同排序方式
  └── 每天两次运行时间不固定
```

### 多账号轮换

```
┌──────────────────────────────────┐
│          Account Pool            │
│  ┌─────┐ ┌─────┐ ┌─────┐       │
│  │闲鱼A│ │闲鱼B│ │闲鱼C│  ...   │
│  └──┬──┘ └──┬──┘ └──┬──┘       │
│  ┌─────┐ ┌─────┐ ┌─────┐       │
│  │淘宝A│ │淘宝B│ │淘宝C│  ...   │
│  └─────┘ └─────┘ └─────┘       │
└──────────────────────────────────┘
```

- 每次运行从池中随机选 1-2 个账号
- 同一账号 24h 内最多用 1 次
- Cookie 加密持久化，避免每次重登

### 淘宝额外防护

- 搜索前必须登录，Cookie 复用
- 不硬刚滑块验证码，遇到就切账号或等下一轮
- DOM 解析为主，不依赖 XHR 监听

## 搜索模块

### 搜索词策略

```
产品名称 → LLM 生成 3-5 差异化搜索词 → 每次运行随机选 2-3 个
```

示例：
```
「中文15天」→ ["15天中文会员", "中文15天 优惠", "15天 中文账号", "短期中文 会员"]
```

### 搜索执行（每次运行）

```
1. 从账号池选 1 个闲鱼账号 + 1 个淘宝账号
2. 对每个 SKU，随机选 2 个关键词
3. 依次搜索，间隔 2-5 分钟
4. 提取前 20-30 条商品
5. 总计约 160 条/次运行
```

## 数据提取

### 主方案：DOM 解析

Playwright 等待搜索结果加载完成后，通过 CSS 选择器提取：
- 商品标题
- 价格（到手价/标价）
- 卖家昵称
- 商品链接
- 销量/浏览量
- 商品图片 URL

### 兜底方案：LLM 视觉识别

DOM 解析无价格数据时 → Playwright 截图 → LLM 识别图片中的价格信息

## 乱价判定

### 价格配置

```yaml
products:
  - name: "中文15天"
    official_price: 9.9
    keywords: ["15天中文会员", "中文15天", "15天中文"]
    platforms: [xianyu, taobao]
  - name: "英文21天"
    official_price: 39.9
    ...
  - name: "中文年卡"
    official_price: 2498
    ...
  - name: "英文年卡"
    official_price: 2198
    ...
```

### 判定流程

```
提取价格 → 低于官方价？→ 否 → 跳过
                      → 是 → LLM 二次确认（排除标题党/引流/赠品）
                           → 确认乱价 → 进入钓鱼流程
                           → 非乱价 → 标记忽略
```

### 边界处理

- 价格明显过低（1元、0.1元）→ 引流贴概率大，标注但不钓鱼
- 价格略低于官方价 → 正常进入钓鱼流程
- 标题/图片与描述不符 → LLM 看截图确认

## 钓鱼溯源模块

### 流程

```
Step 1: 评估可行性（卖家在线？有咨询入口？未重复？）

Step 2: 准备钓鱼身份（专用钓鱼小号，非搜索账号）

Step 3: 执行多轮对话（LLM 按脚本模板执行）
  首轮：「请问这个还在吗？」(自然开场)
  二轮：「怎么买呀？直接拍吗？」(引导交易)
  三轮：「能给个购买链接吗？」(获取渠道)
  后续：根据对方回复动态应对

Step 4: 信息提取（链接/手机号/渠道来源）

Step 5: 记录溯源（写入数据库）
```

### 可配置话术系统

话术脚本由业务部门编辑 `fishing_scripts.yaml`：

```yaml
scripts:
  - name: "标准开场_闲鱼"
    scenario: "first_contact"
    platform: xianyu
    stages:
      - stage: 1
        name: "开场"
        delay_after: "30-90s"
        messages:
          - "老板，这个还在吗？"
          - "在吗？这个XX还有吗？"
        variables:
          XX: ["15天的会员", "英文21天", "年卡", "会员"]
      - stage: 2
        name: "引导购买"
        condition: "对方回复"
        delay_after: "15-45s"
        messages:
          - "怎么买呀？直接拍就行吗？"
          - "能给个链接不？我直接拍"
      - stage: 3
        name: "获取渠道"
        condition: "对方表示可以卖"
        delay_after: "10-30s"
        messages:
          - "好的，你发我个链接吧"
          - "方便给个联系方式不？"
```

### LLM 在钓鱼中的角色

| 功能 | 说明 |
|------|------|
| 变量填充 | 根据上下文选最自然的变量值 |
| 话术微调 | 不改变意图下微调措辞，避免重复 |
| 回复解读 | 判断对方意图（给了/拒绝/没懂） |
| 决策选择 | 根据回复选下一阶段走哪个分支 |

### 专用 vs 搜索账号分离

- 搜索账号：仅用于搜索，保持干净
- 钓鱼账号：仅用于钓鱼，被拉黑不影响搜索

## LLM 接入

统一适配层，支持多模型切换：

```yaml
llm:
  provider: openai_compatible  # openai_compatible | anthropic
  model: deepseek-chat
  api_key: "${DEEPSEEK_API_KEY}"
  api_base: "https://api.deepseek.com"
  temperature: 0.7
```

支持模型：
- DeepSeek（OpenAI 兼容接口）
- 通义千问（OpenAI 兼容接口）
- OpenAI GPT 系列（原生接口）
- Claude 系列（Anthropic SDK）

## 数据存储

使用 SQLite，零配置嵌入部署。

### 核心表

```
listings        - 采集的商品列表（平台/标题/价格/链接/快照时间）
price_alerts    - 乱价告警记录（关联 listing + 判定结果）
fishing_tasks   - 钓鱼任务（关联 alert + 状态/结果）
fishing_logs    - 钓鱼对话日志（完整对话记录）
accounts        - 账号池（平台/类型/状态/最后使用时间）
reports         - 日报记录（汇总数据）
```

### 日报内容

每次运行生成，推送到钉钉群：

```

🟢 本轮覆盖
  · 闲鱼: 32条 | 淘宝: 28条
  · 搜索词: 6个 | 账号: 闲鱼A, 淘宝B

🔴 发现乱价: 5条
  中文15天 | 闲鱼 | ¥6.00 | 官方¥9.90 | 待钓鱼
  英文年卡 | 淘宝 | ¥1680 | 官方¥2198 | 已钓鱼
  ...

🎣 钓鱼结果
  闲鱼ID 12345 → 已获取链接
  淘宝ID 67890 → 对方未回复
  闲鱼ID 11111 → 已获取手机号

📌 本周累计: 乱价23条 | 钓鱼成功12条 | 新溯源3条
```

### 推送方式

HTTP POST → 钉钉自定义机器人 Webhook（Markdown 消息格式）

## 技术栈

| 组件 | 选型 | 理由 |
|------|------|------|
| 语言 | Python 3.10+ | 生态丰富，AI 相关库支持好 |
| 浏览器自动化 | Playwright | 反检测更优，API 现代，微软维护 |
| 数据库 | SQLite | 零配置，嵌入式，单文件 |
| LLM 接入 | OpenAI 兼容 + Anthropic SDK | 多模型支持 |
| 调度 | Windows Task Scheduler | 无需额外服务 |
| 推送 | 钉钉机器人 Webhook | 配置简单 |
